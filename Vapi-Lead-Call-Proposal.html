01

Summary

You are hiring for someone to deploy AI voice agents that follow up leads, answer inbound calls, handle missed calls, qualify prospects, book appointments, and hand hot leads to a human — all connected to your existing CRM and scheduling tools. This proposal covers implementing that, end to end.

The centrepiece — new lead → outbound AI call → qualification → book / live-transfer / follow-up — is not a concept. It is already constructed as two n8n workflows in a running instance, validated with zero errors, with retry and error-alert paths on every external call. What remains is connecting it to your Vapi assistant, CRM, calendar and phone numbers, building the voice agent and script to your offer, adding the inbound and missed-call flows, and running the full test matrix before go-live.

The sections below lay out the system as built, the full scope mapped to the role, the delivery plan, and how testing and monitoring work.

02

The system, as built

An AI phone call is asynchronous: you start it and hang up, then the result arrives minutes later. The pipeline is therefore split into two workflows joined by an ID passed in the call’s metadata.

Workflow 1 — lead in, call out

A lead hits a webhook (from a form, your CRM, or a lead tool). n8n cleans the data, upserts the contact in HubSpot as a lead, then calls the Vapi API to dial the prospect — passing the contact ID, name and source through so the AI can greet them properly and the result can be traced back. A timeline note is logged, and the webhook responds in about a second.

StepNodeWhat it does
1New Lead WebhookPOST /new-lead — receives {name, email, phone, source, notes}
2Normalize LeadSplits the name, lowercases the email, formats the phone to E.164, defaults the source
3Has Phone & EmailMissing either → responds 400 and stops
4Upsert ContactHubSpot create-or-update; sets lifecycle lead / status IN_PROGRESS
5Vapi: Start Outbound CallDials the prospect; embeds hubspotContactId, email, name, source in call metadata
6Log Call InitiatedWrites a QUEUED call engagement to the contact timeline
7Respond / AlertReturns 200; any failure routes to a Slack alert and a 502

Workflow 2 — call ended, route the outcome

When the call finishes, Vapi calls a second webhook with the transcript, recording, and the assistant’s structured analysis. n8n reads whether the lead was qualified, whether they asked for a human, and how the call ended, then picks one of four routes.

hot_transfer
Answered · qualified · asked for a person
HubSpot task “call now” + Slack alert to the sales channel.
book
Answered · qualified
Generates a single-use Calendly link and texts it to the lead.
unqualified
Answered · not a fit
Marks the contact UNQUALIFIED; no outreach.
retry
Voicemail / no answer / busy
Sends a “sorry we missed you” SMS and books a follow-up task.

Every route converges on a single update step: the contact’s lead status and lifecycle stage are set from the outcome, and the full call — summary, transcript, recording link, duration — is written to the HubSpot timeline. Then a 200 goes back to Vapi.

Reliability is built in, not bolted on. Every HubSpot, Twilio and Calendly call retries three times before failing. Failures never disappear: they route to a Slack alert with the lead’s details and the error, and the webhook returns an honest status code (400 for bad input, 502 for an upstream failure) so the caller’s own error handling fires.

06

Implementation plan

Sequential phases. Durations are working estimates and firm up after discovery.

  1. Access & discovery2–3 days

    Accounts and API access (Vapi, CRM, Calendly, Twilio, Slack). Define the call flow, qualification criteria, transfer rules and the target CRM field map. Confirm phone numbers and routing.

  2. Voice agent & script3–5 days

    Build the Vapi assistant. Write and refine the qualification script, objection handling and FAQs. Select and tune the voice. Define the structured-output schema. Bench-test with sample calls.

  3. Pipeline wiring3–5 days

    Connect the two built workflows to your accounts. Add the inbound-answering and missed-call workflows and the SMS-backup sequence. Wire lead sources into the intake webhook.

  4. Test & QA2–4 days

    Run the full matrix below against real numbers and safe test data. Fix what breaks. Verify every CRM write and every response code.

  5. Launch & monitorgo-live + 2 weeks close support

    Activate the workflows, watch the first executions live, stand up the metrics view, and tune script and voice on early call data.

07

Testing & QA

Nothing goes live until this passes. It doubles as the acceptance checklist.

  • Outbound calls fire on new leads and reach the prospect
  • Inbound calls are answered and routed correctly
  • Missed calls trigger the callback / qualification flow
  • Qualification questions run and the structured output is correct
  • Objection handling responds sensibly to common pushback
  • Booking produces a valid Calendly link and the SMS arrives
  • SMS backup and follow-up tasks fire on no-answer
  • Live transfers connect to a human and pass context
  • CRM shows the right contact, lead status, tasks and call log with transcript
  • Error paths alert Slack and return the correct status code
